# Панель провайдера (macOS)

Приложение в меню-баре поверх работающего агента. Считает и берёт задачи не
оно, а агент — отдельный процесс под своим пользователем. Панель, закрытая или
упавшая, узел не останавливает.

## Что уже есть

```bash
cd desktop
npm install
npm run tauri build -- --debug     # → src-tauri/target/debug/bundle/macos/Looma.app
```

Оформление берётся из `../web/src/theme.css`: у оператора и у провайдера должен
быть один продукт, а не два похожих. Копия означала бы две правды о цветах,
расходящиеся с первой же правкой.

Связь с агентом — файл `status.json` в корне агента, который тот переписывает
раз в несколько секунд ([status.py](../agent/looma_agent/status.py)). Не сокет
и не порт: сокет пришлось бы охранять правами, порт — тем более, а панель,
открытая до старта агента, увидит его отсутствие, а не ошибку соединения.

Путь берётся из `LOOMA_ROOT`, иначе `/Library/Application Support/Looma`.
Посмотреть на панель с придуманным состоянием:

```bash
LOOMA_ROOT=/tmp/looma-demo src-tauri/target/debug/bundle/macos/Looma.app/Contents/MacOS/looma-desktop
```

## Как это попадает к провайдеру

Собирается **один раз у нас**, а не на каждой машине:

```bash
bash install/build-pkg.sh          # → dist-pkg/Looma-0.1.0-arm64.pkg
```

Провайдер скачивает этот файл с сайта, открывает двойным щелчком, вводит
пароль администратора (иначе демон не поставить), потом запускает Looma из
Программ и вставляет ключ. Больше от него ничего не требуется.

Что происходит при установке, по порядку:

1. **`preinstall`** останавливает демон. Файлы агента заменяются поверх старых,
   и делать это под работающим процессом нельзя: он держит открытые файлы по
   inode и выглядит живым, а первый же отложенный импорт после подмены берёт
   новый файл рядом со старым — две версии в одном процессе. Ломается это
   позже, в другом месте и без видимой связи с установкой.
2. Файлы распаковываются.
3. **`postinstall`** заводит пользователя, расставляет права и поднимает демон.

Задачи при этом теряются, и это осознанно: узел на время установки выходит из
строя, а оркестратор переносит работу. Плавная замена — дело обновлений по
сети, где агент сливает задачи сам.

Ключ узла установку переживает: его в пакете нет, и `join.key` никто не трогает.

Пакет кладёт три вещи:

```
/Applications/Looma.app                        панель
/Library/Application Support/Looma/runtime     свой питон с агентом внутри
/Library/LaunchDaemons/app.looma.agent.plist   демон
```

Питон свой, а не машинный: системный на macOS — 3.9 и таким останется, агенту
нужен 3.10+. Версия закреплена вместе с контрольной суммой — ссылка без суммы
была бы обещанием, что содержимое по ней не изменится, а его никто не давал.

Архитектура — та, на которой идёт сборка: бинарные колёса (grpcio, lattica)
ставятся под неё, и собрать arm-пакет на Intel нельзя. Для второй запустите тот
же скрипт там.

Ключ при установке не спрашивается: его вводят потом, в панели, а агент до часа
ждёт, пока он появится. Демон, а не агент сессии — узел работает и когда в
систему никто не вошёл. Лог: `/Library/Logs/Looma/agent.log`.

### Подпись, когда появится Developer ID

```bash
LOOMA_SIGN_ID="Developer ID Application: ..." \
LOOMA_INSTALLER_ID="Developer ID Installer: ..." \
  bash install/build-pkg.sh
xcrun notarytool submit dist-pkg/Looma-*.pkg --keychain-profile looma --wait
xcrun stapler staple dist-pkg/Looma-*.pkg
```

Подписывается изнутри наружу: сначала встроенный питон, потом приложение, потом
пакет — подпись на бандле, наложенная раньше его содержимого, становится
недействительной от первого же изменения внутри.

Питону нужны послабления ужесточённой среды ([runtime.entitlements](install/runtime.entitlements)):
он ставит колёса с нативными модулями и грузит torch и mlx, а без них не
запустит ни одной настоящей задачи — и выглядеть это будет как падение чужого
кода, а не как наша подпись.

### Из исходников, для разработки

```bash
sudo bash install/install.sh       # берёт питон с машины
sudo bash install/uninstall.sh     # кэши остаются: в них десятки гигабайт
```

## Чего ещё нет

- **Подпись и нотаризация.** Нужны, чтобы пакет можно было **раздавать**.
  Gatekeeper останавливает не «неподписанное», а «скачанное»: метку карантина
  ставит браузер, и на пакете, собранном у себя, её нет — поэтому проверить всё
  на своей машине можно и без Developer ID (`sudo installer -pkg … -target /`).
  А вот у того, кто скачает файл с сайта, карантин появится, и без подписи
  macOS его не откроет. Подписывать придётся и встроенный питон.
- **Баланс.** Узел знает, что он посчитал, но не знает, во что это оценили:
  заработок живёт у оркестратора, и ему нужен эндпоинт, авторизованный ключом
  узла.
- **DMG.** Собирается отдельно и только при графической сессии: `bundle_dmg.sh`
  ходит в AppleScript и без входа в систему падает.

## Чего нельзя забыть про изоляцию

На Linux задача заперта дважды — отдельным пользователем и контейнером с его
файловой системой. На Mac контейнера не будет: Metal в него не пробрасывается.
Вторую половину даёт песочница ([sandbox.py](../agent/looma_agent/tasks/sandbox.py)),
и она включается сама. Но **дом хозяина закрывается только тогда, когда ни
агент, ни его интерпретатор в нём не живут** — то есть у настоящей установки в
`/Library`. Запущенный из домашнего каталога агент оставляет `/Users` открытым
и говорит об этом; остальные границы работают по-прежнему.
