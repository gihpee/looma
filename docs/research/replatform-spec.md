# ТЗ: переработка клиентской части Looma Float

**Версия:** 0.2 (решения по §12 внесены) · **Дата:** 20 сентября 2026
**Основания:** `ionet-frontend-analysis.md`, `looma-frontend-analysis.md` (оба в этом каталоге)
**Статус:** утверждён по составу; следующий шаг — макеты (этап 1)

---

## 1. Цель и границы

**Цель.** Переупаковать Looma Float по продуктовой модели io.net: три поверхности на своих поддоменах, единая клиентская платформа с двумя смысловыми блоками — **looma-compute** (аренда Ray-кластера) и **looma-intelligence** (инференс и обучение LLM), — новый лендинг с информативной шапкой, новая дизайн-система со светлой темой по умолчанию, пересмотренная админка. При этом сохранить смыслы Looma: распределённая сеть домашних машин, «платформа — первый клиент своей сети», честность в цифрах и текстах.

**В границах:** `web/` (все три поверхности), `docker/edge`, `web/nginx`, конфигурация доменов и сертификата, контракт клиентского API (перечень эндпоинтов, которые должен дать оркестратор). Существующие файлы фронта и edge можно удалять — совместимость с ними не требуется.

**Вне границ:** внутренности оркестратора и агентов, p2p-слой, канал агентов на `:9000` (не меняется — см. переписку по сертификатам), десктоп-приложение `desktop/`.

**Не переносим из io.net:** крипто-слой, лид-формы вместо продуктов, автопопапы, трекеры, тёмные паттерны выбора железа, 20 несемантических серых.

## 2. Продуктовая концепция

### 2.1 Три поверхности

| Поддомен | Поверхность | Для кого | Аналог io.net |
|---|---|---|---|
| `loomafloat.ru` | Лендинг | все | `io.net` |
| `console.loomafloat.ru` | Клиентская платформа | клиент (роль `client`, админ тоже) | `cloud.io.net` + `ai.io.net` |
| `admin.loomafloat.ru` | Админка | роль `admin` | нет публичного аналога |
| `api.loomafloat.ru` | Программный API | SDK, `looma-connect`, интеграции | `api.io.solutions` |

### 2.2 Два смысловых блока и их продукты

```
looma-compute                          looma-intelligence
├─ Ray-кластер (аренда)                ├─ Инференс (OpenAI-совместимый API + чат)
│   визард: узлы → длительность →      ├─ Модели (каталог: платформенные и свои)
│   стоимость → предпросмотр           ├─ Обучение (LoRA: SFT сейчас, DPO по плану TaaS)
│   вытеснения → запуск                └─ Ключи API
└─ (резерв: Задача на GPU — как
    в админке «Задачи», позже)
```

Соответствие продуктовой упаковке io.net:

| io.net | Looma | Комментарий |
|---|---|---|
| Cloud → Virtual Machine / Container | **Compute → Ray-кластер** | VM/контейнеров у нас нет; кластер — единственный compute-продукт, и это честно |
| Container Recipes | **Intelligence → Модели → «Развернуть» с пресетами** | рецепт = модель + движок + точность + требование VRAM |
| Intelligence → Chat | **Intelligence → Чат** | playground с выбором модели, историей, метриками ответа |
| Intelligence → Models (прайс) | **Intelligence → Модели** (каталог + цена за токены) | цена за 1M токенов in/out, как у io |
| Intelligence → Training (Beta) | **Intelligence → Обучение** | форма из Simple/Advanced, но Advanced ограничен нашими полями |
| API Keys & Secrets | **Ключи API** | без Secrets на первом этапе |
| Credits / Billing History | **Биллинг** (баланс кредитов, расход, детализация) | предоплата кредитами, начисляет админ (§12) |
| Get Started чеклист | **Первые шаги** на главной консоли | 4 пункта, не в сайдбаре |
| Managed Services (лид-форма) | — | не делаем |
| Agents / Workflow Editor | — | не делаем |

### 2.3 Ключевые ценности и как они доносятся

| Ценность Looma | Где на лендинге | Где в консоли |
|---|---|---|
| Мощность по требованию, оплата по факту | hero, секция цен | стоимость inline в каждом визарде, «Расход» на главной |
| Сеть домашних машин; узел без входящих портов | секция «Как устроено» (3 факта — сохраняем) | карта сети в Compute («N узлов · M свободно») |
| Платформа — первый клиент своей сети | секция «Как устроено» | Displacement-предпросмотр в визарде аренды (сохраняем) |
| Честные цифры | живое демо с метриками ток/с и TTFT | метрики ответа в чате, loss/шаги в обучении |
| **Сильно дешевле AWS / Selectel** | секция «Цены»: ₽/час кластера по классам карт и ₽/M токенов по моделям, рядом — цена AWS/Selectel и «−N%» | зачёркнутая цена конкурента в карточках узлов и моделей (как у io), все цены и цены конкурентов задаёт админ |
| Свои модели — полная свобода | секция продуктов: «загрузите, дообучите, разверните, снимите — без согласований и заявок» | Модели → «Мои» (деплой любого HF-репо или своего адаптера), Обучение → адаптер → «Развернуть» |

## 3. Архитектура

### 3.1 Домены, edge, сертификат

```
DNS:  loomafloat.ru, console., admin., api.  → один IP (A/AAAA)
Cert: один SAN-сертификат, --cert-name loomafloat.ru (путь не меняется,
      оркестратор и агенты не затрагиваются)

edge (nginx, 80/443, host-сеть)
  server loomafloat.ru        → web:8080  (лендинг)
  server console.loomafloat.ru→ web:8080  (SPA console + /api/* прокси)
  server admin.loomafloat.ru  → web:8080  (SPA admin + /admin/* прокси)
  server api.loomafloat.ru    → orchestrator:8000 напрямую
                                 (/v1/*, /api/*, /connect/*; без SPA)
  HSTS на каждом хосте; порт 80 отвечает ACME на все четыре имени
```

Принцип из текущего nginx сохраняется: **браузерные поверхности ходят на свой origin** (`console.…/api/…` проксируется), CORS не нужен. `api.` — для программных клиентов; там же `looma-connect` (WebSocket `/connect/`).

Cookie сессии: `Domain=.loomafloat.ru`, `Secure`, `HttpOnly`, `SameSite=Lax` — один вход на console и admin. Исправить `secure=` (сейчас зависит от схемы за прокси — пробрасывать `X-Forwarded-Proto` и включить `proxy_headers` в uvicorn).

### 3.2 Структура кода

```
web/
  package.json            pnpm workspace (или npm workspaces)
  packages/ui/            дизайн-система: токены, компоненты, иконки, тема
  packages/api/           типизированный клиент + типы ответов (общий для console/admin)
  apps/landing/           Vite + React, SSG-пререндер главной (vite-plugin-ssr
                          или простой prerender-скрипт) — ради SEO/OG
  apps/console/           Vite + React, роутер с URL на каждый экран
  apps/admin/             Vite + React, тот же ui-пакет
  nginx/                  server-блоки для web-контейнера (по $host)
docker/edge/              server-блоки по хостам, ACME
```

Три сборки вместо одной: лендинг не тащит код консоли, консоль не тащит админку. Общее — в `packages/ui`. Роутер — `react-router` (у консоли ≥15 экранов, самописный роутер себя исчерпал). Данные — `@tanstack/react-query` вместо `usePoll` (кэш, дедупликация, refetchInterval, отмена; принцип «опрос не трогает форму» сохраняется автоматически).

### 3.3 Аутентификация и роли

- Вход на `console.` по почте/паролю (форма как сейчас), регистрация — по приглашению (без изменений, §12).
- `admin.` пускает только `role=admin`; клиент видит страницу «Панель — для администраторов» со ссылкой в консоль.
- Ключи API — только для `api.`; в консоли они выпускаются и отзываются.

## 4. Дизайн-система

### 4.1 Принципы

1. **Светлая тема по умолчанию**, тёмная — переключатель в шапке, хранится в `localStorage`, уважает `prefers-color-scheme` при первом входе.
2. **Акцент — бирюза Looma** (`#29c6de` → для светлой темы затемнить до контраста AA на белом, ориентир `#0e9fb5`; яркая `#29c6de` остаётся для тёмной темы и для свечений в hero лендинга).
3. **Спокойные поверхности**: белый/светло-серый фон, карточки — плоские с 1px бордером и одной мягкой тенью. Убираем `.glass`, внутренние свечения, градиентные подложки карточек. Свечение допускается в одном месте — hero лендинга.
4. **Один акцент на экран**: primary-кнопка — бирюзовая; всё остальное — нейтральное (чёрный текст/белая кнопка с бордером), как у io.net, где цвет = «здесь начинается действие».
5. **Цвет = состояние** (ok/warn/bad/info) — сохраняем словарь `StateBadge`.
6. **Движение**: одна анимация-подпись — «уто́к» при раскрытии ключа и при появлении hero. Weave-reveal по секциям лендинга убираем; `Loom` (станок) остаётся только фоном hero, приглушённым.
7. **Плотность**: body 14px в консоли/админке, 16px на лендинге; ритм 4/8/12/16/24/32/48.

### 4.2 Токены (черновик, финализируются в макетах)

### 4.3 Компоненты (packages/ui)

Базовые: `Button` (primary / secondary / ghost / danger; sm / md / lg), `IconButton`, `Badge`/`StateBadge`, `Card`, `Stat` (label / value / unit / sub / trend), `Table` (сортировка, пустое состояние, sticky header), `Tabs`, `Segmented`, `Input` / `Select` / `Textarea` / `NumberStepper` (− n +), `Toggle`, `RadioCard` (иконка + заголовок + описание + бейдж «Рекомендуем»), `Field` (label + hint + error), `FilePick`, `Modal`, `Drawer`, `Confirm`, `Toast`, `Empty` (иллюстрация-SVG в стиле знака + заголовок + текст + CTA), `Stepper` (шаги с прогресс-полосой) + `WizardFooter` (sticky: Назад / Далее, стоимость слева), `KeyValue` (спеки), `CodeBlock` (копировать), `ProgressPhase` (бар + текст фазы), `NetworkFabric` (полосы узлов — сохраняем, без свечения), `Displacement`.

Иконки: Lucide (единый набор, stroke 1.5), логотипы моделей — SVG-набор (Qwen, DeepSeek, Llama, Mistral, Gemma).

Иллюстрации: не растровые; 5–6 line-art SVG для пустых состояний.

## 5. Лендинг `loomafloat.ru`

### 5.1 Шапка (по образцу io.net, с нашим содержанием)

```
[ announcement-бар: «H100 от X ₽/час · инференс от Y ₽/M токенов — в N раз дешевле AWS → Цены» ]
[ Знак Looma ]   Продукты ▾   Как устроено   Цены   Документация ↗        [Войти] [Начать]

Мега-меню «Продукты» (три колонки, описание под каждым пунктом):
  looma-compute                looma-intelligence            Сеть
  ├ Ray-кластер                ├ Инференс (API + чат)        ├ Как подключить машину
  │  свой код на чужих картах  ├ Модели (каталог и цены)     ├ Как устроено
  └ Цены на кластер            ├ Обучение (LoRA)             └ Документация
                               └ Ключи API
```
Числа в announcement-баре — из публичного прайса (`GET /api/public/pricing`), который заполняет админ. Живых чисел сети (узлы, свободные GPU) на лендинге **нет** — решение §12.

### 5.2 Секции

1. **Hero** — приглушённый `Loom` фоном; H1 «Мощность, когда она нужна» (сохраняем), подзаголовок с двумя продуктами, две CTA: «Начать» (console) и «Попробовать инференс» (якорь на демо). Справа — **карточка сравнения цен**: «H100 ×1 — X ₽/час у нас · Y ₽/час AWS · Z ₽/час Selectel» (наш аналог первого экрана io «70% cheaper than AWS», но с числами из прайса, а не лозунгом).
2. **Продукты** — две большие карточки-блока: looma-compute / looma-intelligence, внутри — по 2–3 пункта с иконками и «Открыть».
3. **Как устроено** — три факта (сохраняем тексты), но плоскими карточками; плюс схема «одна нить от узла» как SVG-диаграмма.
4. **Цены** — два блока с датой актуальности, данные из `/api/public/pricing` (заполняет админ):
   - *Кластер*: таблица по классам карт (RTX 3090 / 4090 / A30 / A100 / H100 …): VRAM, ₽ за GPU-час у нас, у AWS, у Selectel, «−N%». Карточки в стиле `HardwareCard` io: логотип, класс, VRAM, цена с зачёркнутой ценой конкурента.
   - *Инференс*: таблица моделей: имя, контекст, ₽ за 1M входных / выходных токенов, «Открыть в чате».
   - *Обучение*: ₽ за GPU-час (тот же тариф, что кластер, если админ не задал отдельный).
   Формулировка секции: «В N раз дешевле AWS и Selectel» — N считается из прайса, не пишется руками.
5. **Попробуйте сами** — демо-чат (сохраняем), выбор из 2–3 моделей, метрики; `<think>` сворачивается в «ход рассуждения».
6. **Для владельцев машин** — короткий блок: «одно исходящее соединение», «код в песочнице», кнопка «Подключить машину» → документация. (У io это спрятано; у нас поставщики — часть смысла.)
7. **Финальный CTA** + футер (продукты / документация / статус / контакты).

### 5.3 Требования
`title`/`description`/OG на каждую страницу; пререндер главной; ≤300 KB JS; без трекеров; мобильная раскладка от 360px; `user-scalable` не блокируется.

## 6. Консоль `console.loomafloat.ru`

### 6.1 Каркас

```
┌ сайдбар 240px ───────────┬ топбар ─────────────────────────────────────┐
│ Знак · Looma              │ [поиск ⌘K]      Баланс/Расход  Docs ↗  🔔  ☾ [аватар ▾]
│ Главная                   ├─────────────────────────────────────────────┤
│ ▾ Compute                 │                                             │
│    Кластеры               │   контент (max 1280px), hero-блок страницы: │
│ ▾ Intelligence            │   H1 + подзаголовок + CTA                   │
│    Чат                    │                                             │
│    Модели                 │                                             │
│    Обучение               │                                             │
│    Ключи API              │                                             │
│ Биллинг                   │                                             │
│ Настройки                 │                                             │
│ ┌ Первые шаги 1/4 ┐       │                                             │
│ [почта] [Админка →]       │                                             │
└───────────────────────────┴─────────────────────────────────────────────┘
```
URL на каждый экран (`/compute/clusters/:id`, `/intelligence/models/:id`), deep-link и «назад» работают. Мобильный: сайдбар в drawer.

### 6.2 Экраны

**Главная** (`/`) — «Здравствуйте, Имя»; ряд Stat: Расход за месяц · Активных кластеров · Токенов за месяц · Задач обучения; «Первые шаги» (создать ключ → отправить запрос → арендовать кластер → дообучить); «Сеть сейчас» — `NetworkFabric` с легендой; «Ваши ресурсы» — таблица активного (кластеры + обучения) с состоянием и «открыть».

**Compute → Кластеры** (`/compute/clusters`) — hero + «Арендовать кластер»; таблица: имя/id, узлов×GPU, с какого времени, осталось, стоимость, состояние, действия (подключиться / снять). Карточка кластера (`/:id`): состав по рангам, инструкция подключения (`looma-connect` с готовой командой и `api.` URL), лог, стоимость нарастающим итогом, «снять».
**Визард аренды** (3 шага, stepper + sticky-футер со стоимостью):
1. *Узлы* — **здесь и только здесь клиент видит доступные карты** (решение §12): карточки узлов (класс карты, VRAM, RTT, ₽/час с зачёркнутой ценой конкурента) или «выбрать автоматически» + количество; фильтр по VRAM и классу.
2. *Параметры* — длительность (stepper + единицы), метка, библиотеки, точка входа (опционально), «продлевать автоматически».
3. *Проверка* — сводка, **Displacement**-предпросмотр (сохраняем), политика при нехватке узлов (radio: ждать / взять меньше / отменить — наш аналог партиальной аллокации io), итоговая стоимость, «Запустить».

**Intelligence → Чат** (`/intelligence/chat`) — левая панель истории; селектор модели (платформенные + свои развёрнутые); системный промпт; параметры (temperature, max tokens); ответ стримом с метриками (ток/с, TTFT, токены, стоимость запроса); «Показать как код» (curl / python с `api.` URL и ключом-плейсхолдером); `<think>` — сворачиваемый блок.

**Intelligence → Модели** (`/intelligence/models`) — вкладки «Платформенные» / «Мои». Карточка: логотип, имя, контекст, цена in/out, состояние (отвечает / поднимается), «Открыть в чате», «Код». «Мои» — свои модели/адаптеры: кнопка **«Развернуть»** → визард (HF-репо или адаптер из обучения → пресет движка/точности с требованием VRAM и честным «поместится на N узлов» → узлы → стоимость → запуск). Страница модели: стадии по рангам с `ProgressPhase` (сохраняем из админки), метрики, «снять».

**Intelligence → Обучение** (`/intelligence/training`) — список заданий (карточки как сейчас: база · точность · r · время · loss · артефакты); **визард** (Simple / Advanced):
- Simple: метод (RadioCard: SFT — доступно; DPO — «скоро», по плану TaaS), базовая модель (список + HF), датасет (.jsonl + валидация формата + предпросмотр 3 строк), имя.
- Advanced (аккордеон): точность базы (bf16 / nf4), LoRA r / alpha / dropout, LR, epochs, cutoff, batch / grad-accum, узлы. **Не более этого** — не повторять LLaMA-Factory.
- Sticky-футер: оценка стоимости (GPU-часы × ставка) и времени.
Страница задания: график loss/lr по шагам, стадии, лог, артефакты, кнопка «Развернуть адаптер» → визард моделей с предзаполнением.

**Ключи API** (`/intelligence/keys`) — как сейчас (показ один раз, «уто́к»), плюс блок «Как использовать»: base_url `https://api.loomafloat.ru/v1`, примеры curl/python/openai-sdk.

**Биллинг** (`/billing`) — модель: **предоплата кредитами, 1 кредит = 1 ₽**, модуль оплаты не подключается — кредиты начисляет админ. Stat: Баланс · Расход за месяц · Расход всего; таблица операций (начисления и списания) с фильтром по продукту и периоду; экспорт CSV; текущие ставки (₽/GPU-час по классам, ₽/M токенов по моделям). Кнопка «Пополнить» ведёт на экран «Как пополнить: напишите нам» — без формы оплаты. В визардах: Total Cost + «Баланс покрывает» / «Не хватает X ₽ — обратитесь для пополнения» (предупреждение, не блокирует до шага «Запустить»).

**Настройки** (`/settings`) — профиль, пароль, тема, (SSH-ключи — только если появятся VM/контейнеры, пока нет).

### 6.3 Паттерны, которые обязательны на каждом экране
Hero-блок страницы; пустое состояние с иллюстрацией и CTA; стоимость inline до действия; предупреждение, не блокирующее путь; человеческие тексты ошибок; контекстная ссылка «Документация» в топбаре, меняющаяся по разделу; «Код» рядом с любым действием, у которого есть API-эквивалент.

## 7. Админка `admin.loomafloat.ru`

Тот же `packages/ui`, та же светлая тема. Состав экранов сохраняется (Обзор, Узлы, Модели, Обучение, Ray, Задачи, Клиенты, Ключи подключения, Релизы), изменения:

- URL на экран; сайдбар с группами «Сеть» (Обзор, Узлы, Релизы, Ключи подключения), «Нагрузка» (Модели, Обучение, Задачи, Ray), «Клиенты» (Учётные записи, Ставки, Аренды).
- **Модели**: карточка выводит статус из стадий; снятые/упавшие — во вкладку «История»; завершённые обучения не показываются как модели (дефекты A1–A3).
- **Аренды** — новый экран: все лизы клиентов с фильтром, закрытие «зависших» (дефект C1).
- **Ставки и цены** — отдельный экран: ставки за GPU-час **по классам карт**, цены за 1M токенов **по моделям**, цены конкурентов (AWS, Selectel) по тем же классам — всё это публикуется в прайс лендинга и в карточки консоли; история изменений; превью «что увидит клиент».
- **Кредиты** — в карточке клиента: баланс, «Начислить» (сумма + комментарий), история операций. Платёжного модуля нет.
- **Логотипы** — не хардкодятся во фронте. Модели: при добавлении модели с HuggingFace оркестратор тянет аватар организации (`https://huggingface.co/api/organizations/{org}/avatar` / поле `avatarUrl` из `api/models/{repo}`) и кэширует; админ может заменить своим SVG/PNG. Классы карт: справочник «Классы GPU» в админке (имя, VRAM, вендор, логотип) — логотип вендора загружается админом один раз; фронт получает `logo_url` вместе с прайсом (`/api/public/pricing`) и каталогом моделей (`/v1/models`). Нет логотипа — фронт рисует нейтральную плашку с инициалами.
- Обзор: «Требует внимания» с дедупликацией; радиальная схема → та же `NetworkFabric` + список.
- Поле «Админ-токен» уходит из сайдбара в Настройки → «Аварийный вход».
- Health групп — одним запросом (`/admin/groups/health`).

## 9. Нефункциональные требования

- Бюджет: лендинг ≤300 KB JS, консоль ≤600 KB на первую загрузку (route-split), картинки — только SVG.
- A11y: контраст AA для всего текста ≥13px, фокус-стили, landmarks, `aria-*` на модалках, клавиатура в визардах, `prefers-reduced-motion`.
- **Адаптив — обязательное свойство каждого экрана, а не отдельный этап.** Брейкпоинты 360 / 768 / 1024 / 1280+, mobile-first CSS. Правила, зафиксированные макетами:
  - лендинг: шапка → бургер + правый drawer с теми же тремя группами меню и CTA внизу; hero в одну колонку, карточка сравнения под текстом; карточки железа — компактные строки, таблицы моделей — списки;
  - консоль: сайдбар → верхняя панель (бургер, заголовок, баланс) + **нижний tab-bar** (Главная · Кластеры · Чат · Модели · Ещё); primary-действие страницы — FAB над tab-bar; таблицы → карточки; stat-плитки 2×2;
  - визарды: степпер → «Шаг N из M · название» + полоса прогресса; sticky-футер со стоимостью и кнопками на всю ширину; модалки → bottom sheet с ручкой;
  - чат: история и параметры — за кнопками в шапке (drawer / sheet), метрики ответа в одну строку, итог чата под композером;
  - админка: редактируемые таблицы → карточки с полями 3-в-ряд и строкой «Клиент увидит»; sticky «Опубликовать»;
  - touch-цели ≥ 44px, `user-scalable` не блокируется, горизонтального скролла страницы нет.
- Язык: русский; строки вынесены в словарь, чтобы английский добавлялся без правки компонентов.
- Телеметрия: только Sentry (ошибки), без пикселей. Опционально — собственная событийная аналитика в оркестратор.
- SEO: пререндер лендинга, OG-карточка, `robots`, `sitemap`.
- Тесты: `packages/ui` — vitest + testing-library на компоненты с логикой (Stepper, NumberStepper, Displacement); e2e (Playwright) на три сценария: вход, аренда до шага «Проверка», выпуск ключа.

## 12. Решения (приняты 20.09.2026)

| # | Вопрос | Решение |
|---|---|---|
| 1 | Оплата | **Предоплата кредитами**, 1 кредит = 1 ₽. Платёжный модуль не подключаем; кредиты начисляет админ; считаем, что у клиентов кредитов достаточно |
| 2 | Регистрация | По приглашению |
| 3 | Клиентский деплой и обучение | **Делаем в этой итерации**, доступно клиенту |
| 4 | История чата | На сервере не храним; в браузере через `ChatStore`-абстракцию с заделом под серверное хранение |
| 5 | Валюта и язык | Только ₽ и русский |
| 6 | Имена блоков | Латиницей: **looma-compute**, **looma-intelligence** |
| 7 | Макеты | Claude Design; 6 экранов консоли/лендинга + 1 админки (этап 1) |
| 8 | Публичные числа сети | На лендинге **не показываем**; доступные карты клиент видит на шаге «Узлы» визарда аренды |

Дополнительно по ценностям: на лендинге — явное сравнение «сильно дешевле AWS / Selectel» с ценами за час кластера по классам карт и ценами за токен по моделям; все цены и цены конкурентов задаются в админке (§5.2, §7, §8).
